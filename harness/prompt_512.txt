Modern processors have abandoned the assumption that all cores are equal. A contemporary hybrid desktop or laptop processor combines a small number of wide, aggressively clocked performance cores with a larger number of narrow, efficient cores that occupy far less die area. The performance cores support simultaneous multithreading, so each physical core exposes two logical execution contexts that share the same functional units, the same level one cache, and the same level two cache. The efficient cores do not support simultaneous multithreading at all, and instead are grouped into clusters of four that share a single level two cache among them. The memory hierarchy is therefore deeply asymmetric, and the cost of moving a running thread from one core to another depends entirely on which pair of cores is involved. Migrating a thread between the two logical contexts of a single physical core costs almost nothing, because no cache state is lost. Migrating between two physical performance cores costs more, because the level one and level two working sets must be rebuilt from the shared last level cache. Migrating from a performance core to an efficient core in a different cluster is the most expensive case of all, because the thread loses its private cache state, arrives on a core with a narrower issue width, and runs at a substantially lower peak frequency.

The operating system scheduler must decide, thousands of times per second, which runnable thread occupies which logical core. It makes this decision using a virtual runtime accounting scheme that aims to distribute processor time fairly among competing threads, weighted by their assigned priority. This scheme knows nothing about what the threads are actually computing. It cannot distinguish a thread that is saturating the memory bus from a thread that is executing a tight arithmetic loop entirely out of cache. It cannot distinguish a background task with no deadline from an interactive task where a delay of ten milliseconds is immediately visible to a human being. It infers a rough approximation of this distinction from observed sleep behaviour, treating threads that sleep frequently as latency sensitive and threads that consume their full time slice as throughput oriented.

This heuristic was designed for an era in which every core was identical and the only scarce resource was processor time itself. Neither assumption holds on the machine described above.
